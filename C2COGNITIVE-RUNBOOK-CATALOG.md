# C2Cognitive Runbook Catalog

**C2Cognitive v1.0.0  |  Release 1  |  30 August 2026**

## Purpose

C2Cognitive v1.0.0 ships 41 runbook files: 40 operational runbooks plus one template. This public catalog names all
of them so a repository visitor can see the actual procedure surface rather than only a curated subset.

The runbooks themselves remain the operational procedures. This catalog is explanatory.

## Capability families represented by the runbooks

The complete set covers, among other areas:

* discovery, partitioning, per-application index placement, and discovery-cache reuse;
* evidence contracts, exact write planning prerequisites, edit tooling, rollback, and incidents;
* Goal readiness, Goal inheritance, plan-to-doc conversion, and workflow discipline;
* agent dispatch, loadouts, batching, leases/fencing, budget suspension, and context compaction;
* memory/Skill/Wiki lifecycle, preflight recall, failure memory, propagation, and cognitive emergency handling;
* system inventory, model-adapter capability, tool-usage capture, browser-tooling recovery, and untrusted content;
* tests-to-workflow mapping, coverage backfill, post-deploy QA, UI audit, and database migration;
* mobile build/release, device QA, and store submission;
* simplification, ratchet loops, blocker convergence, and progress liveness.

## Authority boundary

Reading this catalog is not equivalent to loading a runbook. The active route in `AGENTS.md` and
`.agent/routes.yaml` determines which procedure is applicable. Runbooks also do not grant target write authority;
write authority remains separately gated by entry mode, Goal state, exact write planning, rollback basis, freshness,
and any required lease/fence state.

See [Control Plane Catalog](C2COGNITIVE-CONTROL-PLANE-CATALOG.md) and
[Repository Coverage Matrix](C2COGNITIVE-REPOSITORY-COVERAGE-MATRIX.md).
