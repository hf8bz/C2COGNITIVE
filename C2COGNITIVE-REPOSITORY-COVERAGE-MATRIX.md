# C2Cognitive Repository Coverage Matrix

**C2Cognitive v1.0.0  |  Release 1  |  30 August 2026**

## Purpose

This is the exhaustive public-documentation coverage ledger for the audited C2Cognitive v1.0.0 English repo-only
package used to build this documentation surface.

The source package contains **286 files**. Of those, **31** are under the internal `docs/`
engineering-reference tree. Per the public-repository packaging decision, those internal documents are not
republished in this public-doc bundle. The remaining **255 non-internal repository files** are mapped
below to a public documentation owner.

A path appearing in this matrix means the public docs account for the shipped surface. It does not mean the public
doc replaces the executable file or grants its authority.

## Coverage result

```text
source files audited                         286
non-internal files path-mapped               255 / 255
internal docs topic-mapped to public guides   31 / 31
source-file surfaces accounted for           286 / 286
unmapped functional surfaces                   0
```

## Internal-doc exclusion

The `docs/` tree is intentionally not included in this public documentation ZIP. Its functional topics are surfaced
through the public root guides and catalogs instead. This matrix therefore treats internal-document **bytes** as
excluded publication material while ensuring the **runtime/control-plane mechanisms they describe** are documented
through public files.

If the installable Core is later refactored to physically remove `docs/` from its own distribution manifest/runtime
path contracts, that is a separate architecture/package change and must be validated against the executable Core.
This public-doc coverage matrix does not claim that such a runtime refactor has already happened.

## Coverage definition

Coverage here means:

1. every non-internal shipped file has a named public documentation owner;
2. every major capability family has a substantive public guide or catalog;
3. the README links to the exhaustive catalogs;
4. no public guide depends on an internal `docs/` link;
5. operational authority remains in the actual shipped control-plane/executable files.
